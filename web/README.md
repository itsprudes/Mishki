# Карточки и космический фон

Примеры карточек из макета: **`cards.html`**.
Демо стеклянных карточек на процедурном фоне: `index.html`.

## Примеры карточек — `cards.html`

Три типа в двух размерах, собраны по узлам макета
`5830-498264` / `5830-498300` / `5830-498331`.

| тип        | lg            | sm          | подложка                          |
| ---------- | ------------- | ----------- | --------------------------------- |
| `Default`  | 312 × 420     | 240 × 320   | `card-lg.png` / `card-sm.png`     |
| `Апельсин` | 312 × 420     | 240 × 320   | `apelsin-card-lg.png` / `-sm.png` |
| `Мишка`    | 244.8 × авто  | 180 × авто  | градиент, без картинки            |

Общее для lg: отступы и радиус 32, `blur(20px)`. Для sm — 24 и `blur(15px)`.

Различия между типами:

- **Default** — `justify-content: space-between`: номер с иконкой сверху,
  заголовок снизу. Номер 56/48px, иконка 48/40px, шеврон 28/24px.
- **Апельсин** — вместо `space-between` используется `gap`, а блок логотипа
  растянут через `flex: 1 0 0` и центрирует логотип в свободном месте.
  Логотип 218 × 105.7 (lg) и 140 × 67.9 (sm).
- **Мишка** — единственный тип **без фоновой картинки**: подложка это
  `linear-gradient(180deg, rgba(138,157,214,0.10), #DFAABF)` плюс
  `backdrop-filter`. Высота не задана — собирается по контенту. Есть
  отдельный слой внутренних бликов
  (`inset 0 1px 2px rgba(255,255,255,.5)` и `inset 0 -32px 56px -24px #fff`).

Про арт мишки: слот 212 × 212 (lg) и 156 × 156 (sm), а само изображение
крупнее — 291 и 214 соответственно. Это не ошибка: арт намеренно выходит
за слот и обрезается краями карточки, так задано в макете.

Ширина `244.8px` у большой карточки мишки — тоже из макета, не опечатка.
Дробная ширина слегка мылит границу на 1x-экранах; если это мешает,
округлите до `245px`.

Фон страницы — `img/mishki-bg.png` (2048 × 2048) из макета. В самом макете
он положен как `background-size: 1920px 1920px` от левого верхнего угла;
здесь взят `cover` + `fixed`, чтобы страница любой высоты выглядела цельно.

Шрифт макета — X5 Sans. Он не поставляется с репозиторием, поэтому в
`font-family` стоит первым, а дальше идёт системный фолбэк. Кегли,
интерлиньяж и трекинг заданы по макету.

## Процедурный фон

### Вариант A — canvas (рекомендуется)

Рисуется один раз под размер вьюпорта, перерисовывается на resize с debounce.
Нет внешних картинок и нет заметного повтора текстуры.

```html
<script src="starfield.js"></script>
<script>
  Starfield.mount(document.body, { seed: 12, angle: 32, base: '#203C92' });
</script>
```

Опции: `seed` (любое число — другой рисунок), `angle` (наклон метеоров в градусах,
по умолчанию 32° вниз-вправо), `density` (множитель количества объектов),
`base` (цвет неба), `tile` (бесшовный режим, см. вариант B).

Всегда держите `background: #203C92` на `body` как фолбэк — канвас появляется
на кадр позже.

### Вариант B — готовый PNG, без JS

`starfield-tile.png` — бесшовный тайл 1024×1024 (стыки не видны, проверено).

```css
body{
  background: #203C92 url(starfield-tile.png) repeat;
  background-size: 1024px 1024px;
}
```

Тайл сгенерирован тем же кодом с `tile: true` — объекты дорисовываются за краями,
поэтому линии метеоров проходят через границу непрерывно.

## Карточка

Одна компонента `.card` плюс модификатор размера. Всё, что различается между
размерами, вынесено в переменные — разметка и базовые правила общие.

|                          | размер 8              | размер 6              |
| ------------------------ | --------------------- | --------------------- |
| ширина × высота          | 245 × 340             | 180 × 250             |
| padding / gap / radius   | 32px                  | 24px                  |
| нижнее свечение          | `0 -32px 56px -24px`  | `0 -24px 48px -16px`  |
| `backdrop-filter`        | `blur(20px)`          | `blur(15px)`          |

```html
<div class="card card--8"> … </div>
<div class="card card--6"> … </div>
```

Высота размера 6 в макете задана не была — взята пропорционально размеру 8
(245 : 340 = 180 : 250). Меняется переменной `--card-h` в `.card--6`.

### Что исправлено относительно экспорта из Figma

- `box-sizing: border-box` — без него padding прибавляется снаружи:
  размер 8 выходил 308.8px вместо 245, размер 6 — 228px вместо 180;
- явная высота — иначе она собирается по контенту (у размера 6 это 171.2px);
- `width: 245px` вместо дробных `244.8px` — дробная ширина мылит границу
  и радиус на 1x-экранах (у размера 6 ширина уже целая);
- префикс `-webkit-backdrop-filter` — Safari до 18 не понимает свойство без него;
- переменные `--Numbers-*` и `--Primary-Bears-Boss-20` объявлены в `:root`.

`backdrop-filter` имеет смысл только поверх неоднородного фона: на плоской заливке
он не даёт ничего, но всё равно поднимает элемент в отдельный композитный слой.
С этим фоном он работает по назначению.

Взят `min-height`, а не `height`: при контенте переменной длины жёсткая высота
приводит к тому, что текст вылезает за пределы карточки.

## Карточка с фоновым изображением

Отдельный тип: подложка-картинка вместо жёлтого градиента, контент прижат
к верху и низу (`justify-content: space-between`, `align-items: flex-start`).

|                    | `.imgcard--lg`    | `.imgcard--sm`    |
| ------------------ | ----------------- | ----------------- |
| размер             | 312 × 420         | 240 × 320         |
| padding / radius   | 32px              | 24px              |
| изображение        | `img/card-lg.png` | `img/card-sm.png` |

Карточка полупрозрачная: фон страницы просвечивает сквозь неё размытым.
Это достигается тремя слоями, как в макете.

### Структура

```html
<div class="imgcard imgcard--lg">
  <div class="imgcard__inner">
    <div class="imgcard__bg" aria-hidden="true">
      <div class="imgcard__tint"></div>
      <img class="imgcard__img" src="img/card-lg.png" alt="">
    </div>
    …контент…
  </div>
</div>
```

- `.imgcard__tint` — сплошной `rgba(138, 157, 214, 0.10)`;
- `.imgcard__img` — картинка с `object-fit: cover`, **`mix-blend-mode: lighten`**
  и собственным `backdrop-filter: blur(20px)` (для размера 6 — `15px`);
- контент обязан быть `position: relative`, иначе абсолютный слой `.imgcard__bg`
  перекроет его.

### Почему mix-blend-mode, а не background-blend-mode

Это главный подвох. В Figma режим наложения слоя смешивает его с тем, что лежит
**под ним на холсте**, то есть с фоном страницы. В CSS такому поведению
соответствует `mix-blend-mode`.

`background-blend-mode` — другое свойство: оно смешивает фоновые слои
**внутри одного элемента** и до фона страницы не дотягивается. Если взять его,
карточка получается полностью глухой: фон не просвечивает, `backdrop-filter`
становится бесполезным, и вид расходится с макетом.

Панель «Copy as CSS» в Figma выдаёт именно неправильный вариант — она схлопывает
два отдельных слоя в одну строку `background` и подменяет `mix-blend-mode`
на `background-blend-mode`. Правильную структуру отдаёт codegen (Figma MCP,
`get_design_context`) — там честно стоит `mix-blend-lighten` на теге `<img>`.

Сравнение обоих подходов бок о бок: `imgcard-compare.html`.

### Что ещё исправлено относительно панели «Copy as CSS»

Исходная строка не работала вообще — карточка не отрисовывалась:

```css
background: url(<path>) lightgray 50% / cover no-repeat, rgba(138,157,214,0.10);
```

В шорткате `background` цвет допустим только в последнем слое. Figma положила
`lightgray` (свой плейсхолдер под изображение) в первый слой, поэтому всё
объявление отбрасывалось как невалидное: computed-значения были
`background-image: none` и `background-color: rgba(0,0,0,0)`.

Также: `box-sizing: border-box` — иначе lg выходил 376 × 484 вместо 312 × 420.

### Светлота карточки зависит от фона

`lighten` берёт поканальный максимум, поэтому чем светлее фон под карточкой,
тем светлее сама карточка. Это не баг, а суть режима — в макете карточки над
яркими участками фона тоже выглядят светлее. Если карточка кажется выцветшей,
дело в яркости фона, а не в CSS.

## backdrop-filter

| карточка                      | backdrop-filter | видно ли |
| ----------------------------- | --------------- | -------- |
| стеклянная `.card--8`         | `blur(20px)`    | да       |
| стеклянная `.card--6`         | `blur(15px)`    | да       |
| с изображением `.imgcard--lg` | `blur(20px)`    | да       |
| с изображением `.imgcard--sm` | `blur(15px)`    | да       |

`backdrop-filter` размывает то, что находится **за** элементом, и виден только
если сквозь элемент что-то просвечивает. Обе карточки полупрозрачны, поэтому
работает в обеих. У карточки с изображением прозрачность даёт не сам PNG
(он непрозрачен на 100%), а `mix-blend-mode: lighten` на нём.

Наглядно: `backdrop-demo.html` — обе карточки с blur и без, поверх одной
и той же яркой подложки с резкими краями.

## Производительность фона

Отрисовка канваса — разовая, но не бесплатная: это ~1500 объектов с
`ctx.filter = blur(...)`. На GPU это доли секунды, но при программном
рендеринге и большом вьюпорте может занять заметное время. Если фон нужен
на очень крупных экранах, уменьшите `density` (например `0.6`) — плотность
объектов и так считается от площади.
